# ⚓ My First Ship Game

> A learning-first naval game project built from scratch to improve my skills in JavaScript, software architecture, game development and clean code.

This repository documents my evolution as a developer through one real and increasingly complex codebase.

The goal is not only to make the game work.

The goal is to understand **why it works**.

---

## 🎯 Project Purpose

`My First Ship Game` is a personal project focused on practical software engineering.

I am building the game manually while learning through real problems that appear during development.

The project explores topics such as:

- JavaScript
- game loops
- rendering
- state management
- NPC behavior
- combat systems
- architecture
- refactoring
- testing
- performance
- multiplayer concepts

---

## 🧭 How I learn in this project

This project does not follow a fixed learning roadmap.

The learning process is driven by the needs of the codebase.

When a new problem appears, I study the concepts required to solve it properly.

A camera problem may lead to coordinate systems.

An NPC problem may lead to state machines.

A large class may lead to SOLID and refactoring.

A multiplayer bug may lead to synchronization and authority models.

There is no predefined order.

**The project itself becomes the curriculum.**

---

## 🔁 Development and learning cycle

The process is intentionally practical:

1. A real problem appears
2. I investigate the cause
3. I study the concepts involved
4. I design a solution
5. I implement it
6. I test and debug it
7. I refactor when necessary

Learning happens as a consequence of building the game.

---

## 🧠 Engineering principles

Some principles guide the project:

- readable code over clever code
- separation of responsibilities
- SOLID where it makes sense
- DRY without overengineering
- composition over deep inheritance
- game logic separated from rendering
- refactoring as part of development

If I cannot explain a piece of code clearly, I probably do not understand it well enough yet.
